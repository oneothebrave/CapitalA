# 美股量化研究系统第一版需求与架构文档

## 1. 项目定位

本项目的目标是构建一个面向美股的量化研究与智能研判系统。

系统不直接承诺预测股价涨跌，也不定位为自动交易机器人。第一阶段目标是对指定股票进行结构化研究，结合行情、财报、SEC 公告、新闻等数据，生成可解释、可回测、可追溯的定性判断。

核心产出包括：

- 趋势评分
- 新闻/公告事件评分
- 基本面评分
- 风险评分
- 综合判断报告
- 回测验证结果

系统原则：

- 没有数据，不输出强结论
- 所有结论必须能追溯到数据和特征
- 大模型用于信息抽取和报告表达，不直接凭空给交易判断
- 回测结果用于验证历史有效性，不代表未来收益保证

## 2. 第一版市场选择

第一版先做美股。

选择美股的原因：

- SEC EDGAR 披露体系标准化，适合结构化处理
- 财报、公告、新闻覆盖更完整
- 美股公司 ticker、CIK、财务 XBRL 数据映射相对清晰
- 更适合先验证研究框架和数据链路

A 股后续可以作为第二市场接入，但不放入第一版范围。A 股需要额外处理政策预期、题材轮动、涨跌停、T+1、龙虎榜、监管问询、游资风格等本土市场特征。

## 3. 第一版功能边界

第一版只支持股票代码输入。

支持：

```text
NVDA
AAPL
TSLA
MSFT
```

不支持：

```text
英伟达
Nvidia
Jensen Huang
Blackwell
AI 芯片
数据中心受益股
某个主题利好哪些股票
```

第一版不做泛化实体识别，也不做主题到股票的自动映射。

但系统内部仍需要维护最小股票注册表，用于数据获取和标准化：

```text
ticker: NVDA
exchange: NASDAQ
company_name: NVIDIA Corporation
cik: 0001045810
sector: Technology
industry: Semiconductors
```

第一版新闻处理边界：

- 只抓与输入 ticker 明确绑定的新闻
- 只抓该公司 SEC filings
- 只处理该 ticker 相关财报、公告和公司新闻
- 不根据人物、产品、供应链、行业主题主动扩展股票范围
- 新闻源如果没有明确 ticker/company 关联，默认不进入主分析链路

## 4. 系统总流程

```text
用户输入 ticker
        ↓
股票注册表校验 ticker / CIK / 公司信息
        ↓
数据采集层
行情 / 财报 / SEC 公告 / 新闻 / 行业数据
        ↓
原始数据层
保存原始 JSON、HTML、文本、行情数据
        ↓
标准化数据层
统一 ticker、CIK、时间戳、币种、字段格式
        ↓
特征工程层
趋势、动量、波动、成交量、估值、财务、新闻情绪、事件类型
        ↓
研究与回测层
验证信号过去是否有效
        ↓
信号评分层
趋势分、新闻事件分、基本面分、风险分、综合分
        ↓
报告生成层
输出定性判断、依据、风险、置信度
```

## 5. 数据模式

系统需要支持三种数据模式。

### 5.1 严格数据模式

只使用用户提供的数据。

适合：

- 研究复现
- 回测验证
- 对固定样本做离线分析

优点：

- 可复现
- 边界清楚
- 成本低
- 适合调试

缺点：

- 数据可能过期
- 不能覆盖最新事件
- 数据缺失时结论受限

### 5.2 自动研究模式

用户只输入 ticker，系统主动获取公开数据后分析。

适合：

- 分析现实中的当前股票
- 每日自动更新
- 构建长期研究平台

系统需要自动获取：

- 最新股价与历史行情
- 成交量与波动数据
- SEC 公告
- 财报数据
- 相关新闻
- 行业与指数表现

### 5.3 混合模式

用户数据为主，外部数据用于补充和校验。

适合：

- 用户已有专有数据
- 需要用公开数据补齐新闻、公告、行情
- 研究报告需要引用最新信息

## 6. 新闻时间跨度与权重

新闻不应只设置一个统一时间窗口。应按研究周期分层处理。

### 6.1 新闻时间层级

```text
长期背景层：6-24 个月
中期趋势层：1-3 个月
短期催化层：1-10 天
盘中事件层：当天/小时级
```

长期背景层用于识别行业趋势和公司长期逻辑，例如 AI 基础设施需求、数据中心投资、电力需求、芯片供需变化等。

短期催化层用于捕捉近期价格波动触发因素，例如财报、评级调整、监管事件、重大订单、产品发布、诉讼、管理层变动等。

### 6.2 初始权重建议

短线判断，1-5 个交易日：

```text
近期新闻：50%
中期新闻/公告：25%
长期主题：25%
```

波段判断，1-4 周：

```text
近期新闻：30%
中期新闻/公告：40%
长期主题：30%
```

中期判断，1-6 个月：

```text
近期新闻：15%
中期新闻/公告：35%
长期主题：50%
```

这些权重只是初始假设，后续必须通过回测校准。

### 6.3 新闻评分公式

新闻影响分不应只看发布时间，也不应只做情绪分类。建议使用：

```text
新闻影响分 =
事件强度 × 来源可信度 × 新颖性 × 时间衰减 × 股票相关度
```

解释：

- 事件强度：财报、业绩指引、回购、并购、诉讼等强事件高于普通评论
- 来源可信度：公司公告、SEC、交易所、权威媒体高于社交媒体
- 新颖性：重复转载降权，首次披露升权
- 时间衰减：越近权重通常越高，但长期主题可保留慢衰减
- 股票相关度：第一版只接受明确绑定 ticker/company 的新闻

## 7. 数据采集层

模块建议：

```text
data_ingestion/
  market_data/
  sec_filings/
  fundamentals/
  news/
  reference_data/
```

### 7.1 market_data

职责：

- 获取美股历史日线行情
- 获取成交量
- 处理拆股、分红、复权
- 获取基准指数和行业 ETF 数据

第一版最低要求：

- 支持最近 1-5 年日线数据
- 支持 open、high、low、close、adjusted close、volume
- 支持 SPY / QQQ 作为基准

### 7.2 sec_filings

职责：

- 根据 CIK 获取 SEC filings
- 处理 10-K、10-Q、8-K
- 保存 filing 元数据和原文链接
- 提取 filing 发布时间、报告期、表单类型

SEC EDGAR 提供 submissions 和 XBRL company facts API，可作为第一版官方财报和公告数据源。

### 7.3 fundamentals

职责：

- 从 SEC XBRL 或数据供应商获取财务指标
- 标准化收入、利润、毛利率、经营现金流、负债、股本等字段
- 构建季度和年度财务时间序列

第一版重点指标：

- revenue
- gross profit
- operating income
- net income
- operating cash flow
- free cash flow
- total assets
- total liabilities
- shares outstanding

### 7.4 news

职责：

- 获取与 ticker 明确关联的新闻
- 保存标题、正文、来源、发布时间、URL
- 去重
- 标准化时区
- 提取摘要、情绪、事件类型、影响方向

第一版不做：

- 全市场新闻扫描
- 主题到股票映射
- 人物到股票映射
- 产品到股票映射
- 社交媒体情绪扫描

### 7.5 reference_data

职责：

- 维护 ticker、CIK、交易所、公司名称、行业等基础映射
- 为数据采集提供标准标识

第一版可以先使用本地表或轻量数据库表。

## 8. 数据存储层

建议第一版采用：

```text
PostgreSQL：结构化主库
DuckDB：本地研究、批量分析、回测加速
文件系统：保存原始 JSON、HTML、新闻正文、报告
```

数据分层：

```text
raw_data：
原始 JSON、HTML、新闻正文、公告原文，不覆盖

normalized_data：
清洗后的行情、财报、新闻、公告

feature_store：
每天每只股票的特征快照

research_results：
回测结果、实验参数、模型版本

reports：
生成过的分析报告
```

设计要求：

- 原始数据必须保留
- 标准化结果可以重算
- 特征必须带计算日期和数据截止时间
- 回测必须记录参数和代码版本
- 报告必须能追溯到使用的数据快照

## 9. 标准化与时间对齐

这是量化系统最容易出错的部分。

必须统一：

- ticker
- CIK
- 交易日历
- 时区
- 财报发布时间
- 新闻发布时间
- 行情复权方式
- 数据可见时间

第一版必须避免未来函数。

示例：

```text
如果系统在 2024-05-01 收盘后生成信号，
只能使用 2024-05-01 当时已经公开的数据。
不能使用之后修正的财报、之后发布的新闻、之后确认的趋势。
```

每条数据至少应记录：

```text
event_time：事件发生时间
published_at：公开发布时间
ingested_at：系统采集时间
available_at：策略可使用时间
```

回测时必须使用 `available_at` 判断数据是否可用。

## 10. 特征工程层

模块建议：

```text
features/
  price_features.py
  volume_features.py
  fundamental_features.py
  filing_features.py
  news_features.py
  risk_features.py
```

### 10.1 价格特征

- 1 日、5 日、20 日、60 日收益率
- 均线位置
- 均线斜率
- 新高/新低
- 最大回撤
- 相对 SPY / QQQ 强弱

### 10.2 量能特征

- 成交量相对 20 日均值
- 放量上涨
- 放量下跌
- 缩量回调
- 异常成交量

### 10.3 基本面特征

- 收入同比/环比增长
- 利润同比/环比增长
- 毛利率变化
- 经营现金流变化
- 负债率变化
- 每股指标变化

### 10.4 估值特征

- PE
- PS
- EV/EBITDA
- 估值历史分位
- 与同行估值比较

第一版如果估值数据源不足，可以先弱化估值特征。

### 10.5 新闻/公告特征

新闻不只做情绪，要提取事件。

事件类型示例：

- earnings_result
- guidance_update
- analyst_rating
- product_launch
- major_contract
- regulation
- lawsuit
- management_change
- merger_acquisition
- buyback
- dividend

每条新闻或公告输出：

```text
sentiment: positive / neutral / negative
event_type: earnings_result
impact_horizon: short / medium / long
impact_direction: positive / neutral / negative
importance: 0-100
confidence: 0-100
evidence: 摘要证据
```

### 10.6 风险特征

- 财报日临近
- 波动率异常
- 估值过高
- 新闻负面集中
- 监管/诉讼事件
- 价格远离均线
- 大盘风险上升

## 11. 回测系统

回测系统不是预测系统，而是验证系统。

它回答：

```text
如果这套信号规则在历史上真实运行，会表现如何？
```

必须模拟：

- 当时可见的数据
- 信号生成
- 买卖规则
- 交易价格
- 手续费
- 滑点
- 仓位限制
- 调仓周期
- 现金变化
- 持仓变化

第一版回测要求：

- 支持单只股票
- 支持日线级别
- 支持固定规则信号
- 支持买入、卖出、空仓
- 支持交易成本参数
- 输出交易明细
- 输出绩效指标

核心指标：

- 总收益
- 年化收益
- 最大回撤
- 波动率
- Sharpe Ratio
- 胜率
- 盈亏比
- 交易次数
- 换手率
- 与 SPY / QQQ 的相对收益

回测必须记录：

```text
strategy_name
strategy_version
feature_snapshot
start_date
end_date
universe
transaction_cost
slippage
benchmark
code_version
created_at
```

## 12. 信号评分层

第一版使用可解释多因子评分，不优先使用复杂深度学习模型。

建议评分项：

```text
trend_score
momentum_score
volume_score
fundamental_score
valuation_score
news_score
event_score
risk_score
composite_score
```

初始综合分可以使用规则权重：

```text
composite_score =
trend_score × 25%
+ fundamental_score × 20%
+ news_event_score × 20%
+ industry_score × 15%
+ valuation_score × 10%
- risk_penalty × 10%
```

注意：

- 第一版权重是研究假设
- 权重必须允许配置
- 权重必须通过回测校准
- 报告中必须说明信号强弱和风险来源

## 13. 报告生成层

报告生成层可以使用 LLM，但必须基于结构化输入。

LLM 输入：

- ticker
- 公司基础信息
- 行情特征
- 财务特征
- 新闻/公告摘要
- 评分结果
- 回测统计
- 风险标签

LLM 输出：

- 综合判断
- 核心依据
- 行情与技术面
- 基本面与估值
- 新闻/公告影响
- 行业与宏观背景
- 风险因素
- 未来观察点
- 置信度

报告要求：

- 不得编造数据
- 不得输出无依据强结论
- 必须区分事实、推断和假设
- 必须说明数据截止时间
- 必须说明主要风险
- 必须说明结论推翻条件

## 14. 推荐开发架构

第一版建议采用模块化单体，不建议一开始拆微服务。

建议目录结构：

```text
backend/
  app/
    api/
    core/
    data_ingestion/
      market_data/
      sec_filings/
      fundamentals/
      news/
      reference_data/

    scoring/
    backtesting/
    reports/
    jobs/
    storage/
  tests/
  scripts/
  notebooks/
frontend/
  src/

```

推荐技术栈：

```text
Python：数据处理、特征工程、回测、NLP
FastAPI：后端 API
PostgreSQL：结构化主库
DuckDB：本地研究和批量分析
Pandas / Polars：数据处理
SQLAlchemy：数据库访问
React / Next.js：前端
APScheduler / Prefect / Dagster：任务调度
```

MVP 可以更简单：

```text
Python + FastAPI + DuckDB + 文件系统 + 简单前端
```

数据库和外部服务可以逐步增强，不应在第一版过早复杂化。

当前骨架阶段已确认：

- 包管理工具使用 `uv`
- 后端框架使用 `FastAPI`
- 暂不接 PostgreSQL
- 暂不接 DuckDB，只预留后续接入空间
- 先使用文件系统目录保存原始数据、标准化数据、特征结果和报告
- 暂不创建 `frontend/`
- 后续再决定主要交互入口是前端、CLI，还是两者结合
- 初始化 git 仓库

## 17. 主要风险

### 17.1 数据风险

- 免费行情数据可能不稳定
- 新闻源可能缺失或重复
- 财报字段在不同公司间不完全一致
- 历史新闻时间戳可能不准确

### 17.2 研究风险

- 过拟合
- 未来函数
- 样本选择偏差
- 幸存者偏差
- 权重调参导致历史表现虚高

### 17.3 模型风险

- LLM 可能误读新闻
- 情绪分类不能等同于股价影响
- 事件影响方向可能依赖市场预期
- 报告表达可能显得过度确定

### 17.4 实盘风险

- 回测收益不代表未来收益
- 交易成本和滑点会侵蚀收益
- 财报日和突发事件可能导致跳空
- 中国大陆用户交易美股还涉及合规、外汇、税务和券商限制

## 18. 第一版开发优先级

建议按以下顺序开发：

```text
1. 项目骨架
2. ticker 注册表
3. 行情数据采集
4. SEC filings / fundamentals 采集
5. ticker 绑定新闻采集
6. 数据标准化与存储
7. 价格和量能特征
8. 新闻/公告事件特征
9. 简单评分模型
10. 单股报告生成
11. 单股回测系统
12. API 和前端展示
```

优先级判断：

- 先保证数据链路正确
- 再做特征
- 再做评分
- 再做报告
- 最后优化模型

- 第一版做美股

- 第一版先做单股分析
- 第一版使用可解释规则评分
- 第一版必须包含回测验证
- 第一版使用模块化单体架构
